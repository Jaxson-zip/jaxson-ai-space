### 真实联调发现的适配与启动问题

腾讯 2.4.9 的 inbound.js 只设置 From，没有 SenderId；核心 before_dispatch 使用 SenderId，导致收件插件无法匹配扫描者身份。固定发布包 SHA256 校验后补齐 SenderId，保留 AccountId 与 MessageSidFull；真实源码构造片段回归先失败后通过。补丁已部署，重启后的实际 fp 保存、手机回执和服务端重放去重均已验证。

官方 Docker entrypoint 在每次启动先运行 doctor --fix，首次约四分钟，还自动加入 codex 默认运行插件。配置改为直接 Node 启动，安装准备阶段仍显式验证配置；网关最多两核、768MB。容器换实例后旧状态租约暂未过期（核心 TTL 五分钟），启动拒绝重叠持有者。固定 hostname 与 60 秒优雅停机，后续同主机进程身份更容易判定；不手工删除租约或账户状态。

原版网关有明显分发延迟：SenderId 修复后的首条 fp 约 44 秒，约 40 秒发生在 before_dispatch hook 之前，保存 hook 约 2.7 秒；后续普通文字也约 36 秒，hook 本身只需 33 毫秒。因此不是仅首次冷启动慢。

私人收件模式加入受版本哈希约束的直接入口：本人鉴权之后、媒体/斜杠指令/agent 路由/会话入队之前调用相同的私人收件 handler，返回文本时使用腾讯原有发送函数与原消息 context token。保留频道、账号、发送者、会话及 provider 消息 ID，继续使用后台事务及去重；未授权、群聊及无 context token 均不保存；媒体只返回文字说明。关闭私人收件模式仍走原腾讯路径。此模式不提供通用微信 AI 对话，也不执行其他插件发送回调。
