## 已确认的问题

1. 首页/index.html/config.js 被 Caddy 强制改成 Cache-Control: no-store，覆盖作品站本来的浏览器重验证策略。
2. Caddy 没有解析 Cloudflare 的真实访客地址，API 反代删除 X-Real-IP；访问日志样本也未使用正确访客地址，对话限流会按代理跳点识别客户端。

## 两份需要同步的文件

- 正在挂载：`/opt/jaxson-releases/f7382486f8514a88dc39a4fbaf30d75a8d1ff0a9/Caddyfile`
- 当前发布副本：`/opt/jaxson-releases/48b21cd9b2815fd1ba0d145d6290d3b891c381db/Caddyfile`

只更新挂载文件，未来部署会从当前发布副本复制旧配置；只更新当前发布副本，现有 Caddy 不会使用它。因此必须备份并同步两份。操作开始时重新核对挂载、current 和两份内容，若已变化则停止，重新评估。

## 修改内容

1. 删除唯一的 `@page path / /index.html /config.js` 匹配及 `header @page >Cache-Control "no-store"` 覆盖。缓存头交由 portfolio 服务返回；PDF 和 404 保持 no-store。
2. 在文件开头增加与仓库 `docker/Caddyfile` 相同的全局 servers 配置：可信代理为 private_ranges 和官方 Cloudflare IPv4/IPv6 段，client_ip_headers 为 CF-Connecting-IP。官方网段已在本次核对。
3. 在 web:3000 的 API 反代中，将唯一的 `header_up -X-Real-IP` 改为 `header_up X-Real-IP {client_ip}`，保留删除原始 CF-Connecting-IP 和 Forwarded 的处理。
4. 保留服务器原有的 5 个站点入口、其他站点路由及上游地址。生产文件包含本仓库模板没有的其他站点，不能整份替换成仓库模板。

候选使用生产 Caddy v2.11.7 通过内存适配和配置校验（均退出 0），随后在获得站长确认后写入。相同版本的本地 Caddy 配置校验和隔离代理 HTTP 演练也已通过。

## 应用及验收

1. 核实当前配置内容及挂载仍与本次只读结果相符，为两份文件分别创建带时间的受限备份，记录校验值。

5. 匿名验收首页、项目接口和 AI 路由均可访问；首页/index.html/config.js 的 Cache-Control 应为 public, max-age=0, must-revalidate，PDF/404 仍 no-store。
