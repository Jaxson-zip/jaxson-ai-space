# 作品站性能优化（2026-10-07）

## 已复现的负担

- 首屏背景 PNG 2,472,217 字节，人物 PNG 1,772,842 字节，共 4,245,059 字节。
- 履历图片额外 1,002,455 字节，原先在首屏一起加载。
- 外部 Google Fonts 样式表阻塞首次绘制，中文字体存在额外外网依赖。
- 滚动事件重复查询布局并更新导航；弹窗对整个长页面做模糊和缩放，叠加全屏背景模糊；人物常驻 `will-change: filter`。
- 服务器内部首页约 26 ms，CMS 项目接口约 100 ms；采样时负载 0.15，可用内存约 2.3 GB。公网请求时间与网络链路有关。

## 修改

- 原图保留，页面改用 WebP；首屏图片最大组合 310,226 字节（下降 92.69%）。移动端提供更小版本，图片明确尺寸、异步解码，后续人物懒加载。
- 字体自托管；原有英文和中文字体保留，中文使用子集与系统字体回退。首屏无第三方字体样式表依赖。
- 构建时内联公共 API 地址，省去阻塞 HTML 解析的配置脚本请求；API 连接提前建立。
- 去掉全屏和固定导航等处的背景模糊，弹窗以深色遮罩区分层次；导航仅在章节变化时更新，指针读写合并到每帧一次，屏外提示动画暂停。
- 带内容哈希的图片和字体缓存一年；其他资源支持 ETag / 304；HTML、配置保持 no-store。HEAD 不读取整个文件，GET 通过流输出。

## 验证与维护

```powershell
node --test apps/portfolio/scripts/*.test.mjs
```

回归包含首屏图片体积上限、第三方字体样式表依赖、实际 HTTP 重复请求 304、HEAD 和入口缓存策略。已观察这些检查在修改前失败、修改后通过。

图片重新生成：`python apps/portfolio/scripts/optimize-images.py`（需要 Pillow）。生成后更新 HTML 中的哈希路径。字体许可证见 `apps/portfolio/public/fonts/`。

不以文件体积下降推断 FPS；浏览器实际帧率仍取决于设备、屏幕尺寸及网络。没有新增会改变章节高度的按需布局。

## perf2：减少项目读取的额外连接

- 正式作品站改为同域 `/api/showcase-projects`，服务器经 Docker 内网读取固定的匿名 CMS 接口；后台域名预连接不再随首屏创建。
- 公开项目在作品站进程内缓存最多 10 秒，并发读请求合并。HTTP 响应保持 no-store，不给浏览器或 CDN 留存项目 JSON；发布和撤回最多等待此短时缓存到期，已打开页面仍需刷新。
- CMS 故障不返回过期数据，登录凭据不转发，接口只支持公开作品读取；上传图片保持公开 HTTPS 地址。下载简历也改为 no-store。
- 6 项 Node HTTP/资源回归通过；包括匿名转发、凭据隔离、并发合并、撤回和错误恢复、封面地址与响应体积限制。
- 服务器临时容器比较的项目 slug 与真实 CMS 相同；上线后首页、同域作品、CMS、AI、简历均 HTTP 200。当前没有新的浏览器 FPS 或同条件访问速度基准，不声称具体提速比例。
