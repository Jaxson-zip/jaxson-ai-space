# 本机异地备份与告警实施计划

**目标：**按本人选择，将完整生产快照加密后下载到本机，并用本机检查公网可用性；密钥和邮件凭据不提交仓库。

**架构：**服务器只持有恢复公钥，快照合并 CMS 原备份、网关配置、微信账号/context 与 SQLite 在线快照。专用 SSH 下载密钥只能执行固定的加密文件导出命令。恢复私钥留在本机受限目录；下载后认证解密、校验内部归档和数据库格式，不自动恢复生产。每天下载并在登录后补跑；公网检查每五分钟一次，连续失败两次只向本人发一次告警，恢复发一次通知。

**授权：**本人要求继续完善，明确选择先备份到这台电脑。沿用现有服务器、邮箱与精确本人身份；本轮直接执行，不另建子任务或提交混杂工作区。

**技术：**Python cryptography/Paramiko、RSA-OAEP-SHA256 + AES-256-GCM、SQLite backup API、systemd、Windows 当前用户计划任务。

- [x] 先测试加密往返、错误密钥、篡改、截断、不覆盖已有文件；实现流式加密与认证解密，私钥不上传。
- [x] 先测试归档范围、路径穿越/链接拒绝和 SQLite 快照；实现固定目录备份包，不归档运行日志和缓存，不复制活动 SQLite 文件。
- [x] 增加备份服务加密导出步骤，原备份失败告警覆盖导出失败；备份原配置后上线，验证定时器和新快照。
- [x] 设置仅下载固定加密快照的 SSH 公钥限制，完整下载到本机；拒绝非成功/不完整文件，实际解密和校验；恢复私钥与数据 ACL 限本人和 SYSTEM。
- [x] 先测试监测失败阈值、恢复、通知失败保留重试；实现固定公网 URL 监测，既有 SMTP 仅向本人发信，不附带响应正文或日志。
- [x] 安装本机备份与监测计划任务，验证真实执行结果；明确电脑离线不能持续监测或下载，邮件收件需本人确认。
- [x] 更新当前状态、备份位置、恢复说明和未完成事项。

**不在本轮范围：**租用新存储、部署第二台监测服务器、公开备份、直接恢复生产、清除历史快照、企业微信/公众号、CI 凭据变更。
