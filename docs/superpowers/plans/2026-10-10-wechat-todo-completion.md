# 微信待办联调收尾

**目标：**沿用已验收的本人微信和实际 Todo 数据库，补齐重放保护、到期提醒、绑定码和准确的连接状态。

**授权与范围：**本人选择实际 Todo 接入并要求继续完善。采用现有私人数据路径，不新增微信扫码收件进程；不修改公开 CMS 数据。本机 Todo 原分支保留，从线上 `33568fe` 创建独立 worktree。

## 设计与边界

- 网关先在私有 SQLite 领取 provider message ID，再请求 Todo，保存成功回复。跨进程重放返回原回复；同 ID 内容不同拒绝。崩溃或超时留下不确定状态，不自动重发。完成回复保留 30 天；不确定记录保留到人工核查。这不是跨网关与 Supabase 的原子事务或无限期 exactly-once 保证。
- 复用 Todo 提醒表，增加本人身份范围内的领取/确认 API。网关原生服务每分钟领取到期任务，使用已登录腾讯模块与持久会话 context 发送。确认成功后再标记已发送。缺少会话 context 不领取；不发送启用时间之前的历史提醒，不公开发送网关端口。
- 提醒发送也持久记录。确认请求失败后只补确认，不重发；网络结果不确定时停止自动发送，保留人工核查入口与日志。每轮数量有限，不日志打印任务内容、身份或密钥。
- Todo 已登录用户通过现有一次性绑定码 API 绑定；新增只读绑定状态，明确显示 OpenClaw 绑定与独立网站扫码是不同路径。已绑定时提示避免重复扫码。
