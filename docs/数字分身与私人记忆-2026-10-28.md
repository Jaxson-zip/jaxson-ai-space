# 数字分身与私人记忆：下一阶段工作稿

日期：2026-10-28（Asia/Shanghai）。状态：方向已确认，未实施部分均列为待办。

最新优先级：用户已要求暂缓知识库与记忆工作，先测试和修复整体 UI/交互，后续再整理导入。以下保留为工作稿；不继续访谈或扩展记忆功能。

## 目标和当前证据

同时建设公开分身和私人记忆，保持两个入口、两套读取权限。公开分身能解释本人经历、贡献和选择理由；私人助手能围绕已确认的经历、目标和复盘持续跟进。以真实问题的回答覆盖度、准确性和更新效果衡量进度，不以条目数量代表“像本人”。

- 本地 SQLite 预览起始基线：项目 2 条、经历 1 条，补充 AI 知识、复盘、记忆均为 0。该数量不代表生产服务器；本轮没有读取生产私人记录。
- 首次访谈已通过现有私人接口保存为 1 条本地复盘和 1 条 candidate 记忆，未确认、未公开。正文仅在忽略的本地数据库中，不写入仓库或日志。
- `/api/chat` 只加载明确公开的项目、经历、荣誉和 AI 知识，不读取私人记忆。
- 现有流程为：复盘 → 规则提炼候选 → 人工确认 → 私人正式记忆 → 单独创建不公开的 AI 知识草稿 → CMS 审核公开。确认私人记忆不等于公开。
- `memory-extractor.ts` 当前按字段和关键词摘取内容，主要服务技术复盘；尚无私人聊天检索、人物画像、事实冲突处理和完整修订关系。
- 当前本地预览未配置外部回答模型，回答属于公开资料整理，不能据其复述风格评价最终分身的表达能力。
- 对话历史会发送给回答模型，但检索查询只用最后一条问题；省略名称的追问可能缺少检索上下文，需单独回归验证。

## 两条通路

| 环节 | 公开分身 | 私人记忆与助手 |
| --- | --- | --- |
| 入口 | 首页、`/ai`、公开 `/api/chat` | 已鉴权的 `/studio`；私人聊天接口与交互待建设 |
| 读取 | 明确公开且仍有效的事实 | 本人的正式私人记忆及当前会话信息 |
| 新材料 | 项目故事、参与范围、选择理由和公开问答 | 访谈、复盘、目标和本人选择收录的历史材料 |
| 确认 | 核对事实及对外措辞 | 先生成候选，再确认；未经确认不作为长期事实 |
| 公开关系 | 读取经过审核发布的公开副本 | 原文保持私有；公开副本可删减、改写 |
| 更新 | 撤回后不再供新回答使用 | 记录来源、发生及确认时间、修订与替代关系 |

## 实施顺序与访谈方式

1. **先收集真实材料。** 每次围绕一个事件询问“背景—本人选择—理由—结果—公开范围”，整理成待确认材料；先从本站和实习经历入手。
2. **完善人物与记忆结构。** 区分身份背景、项目事件、方法、表达偏好、目标和待核实事项，补上时间及修订关系。新增字段或分类时准备正式迁移，沿用既有迁移发布要求。
3. **实现私人检索对话。** 使用独立接口与统一鉴权；候选供审阅，正式记忆供私人回答引用。更正应明确更新，不能静默合并冲突事实。
4. **完善公开表达与追问。** 只读取审核后的公开副本；承接指代明确的追问，缺少依据时澄清；使用本人确认的表达样例，不凭提示词虚构人格。
5. **形成日常积累流程。** 本人主动提交的会话、微信复盘等生成可编辑候选，去重并提示需要确认的变化；历史导入先明确来源与范围。

访谈按项目动机、具体决定、本人及工具分工、失败与调整、可核验结果、公开范围依次进行。本人暂时记不清时，可以先解释现有代码并提供设计理由的假设；假设必须标记待核实，不能写成本人曾作出的决定，也不能当作已确认记忆。

## 架构讲解材料：实现事实与理由推演分开

下表供理解项目，不代表已核实的历史决策过程或任何人的个人贡献。

| 代码能确认的实现 | 可以怎样理解 | 理由的性质 |
| --- | --- | --- |
| 首页由独立 portfolio 静态服务提供；Next.js/Payload 负责 CMS、AI 和详情 | 公开门面与内容、AI 服务分工；首页直接向 API 提问 | “便于分别维护、部署和处理缓存”是从结构反推的工程解释，历史动机待核实 |
| 公开 AI 只读取公开资料；私人工作台与记忆接口单独鉴权 | 对外介绍与私人积累使用不同读取边界；私人记忆可另行整理成公开草稿 | 读取限制可核实；是否由本人最初提出待核实 |
| AI 从 CMS 公开记录检索，向量索引辅助相关性；保存内容后 worker 异步更新索引 | 先查资料，再组织回答；资料更新和回答能力不依赖把个人事实训练进模型 | 实现可核实；原先选型理由与个人贡献待核实 |
| 项目资料包含角色及公开参与说明 | 技术清单与个人实际分工可以分别说明 | 字段可核实；不能从仓库技术栈反推出本人独立实现了全部功能 |

## 验收与本轮边界

- 公开分身能回答项目动机、实际负责范围、具体选择理由，均追溯到本人确认的公开材料；追问不丢失指代，切换话题不误套旧项目。
- 公开读取路径取不到私人复盘、目标或私人会话内容。
- 私人助手能检索正式记忆并显示来源、时间；候选不被说成已确认事实。
- 更正后旧版本不再主导回答；撤回公开副本不删除私人原文，也不继续暴露撤回内容。
- 使用本人确认的常见问答和表达样例评估效果，再判断是否足以称为数字分身。

本轮完成代码与本地数量核对、方向记录及第一条候选收录。尚未增加私人聊天接口、修改模型配置或写入生产；推演的架构理由未写入人物记忆或公开知识库。
