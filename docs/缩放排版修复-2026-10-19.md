# 作品区缩放排版修复（2026-10-19）

## 根因

原作品区左右布局仅在 CSS 视口同时满足宽度至少 1200px、高度至少 760px 时生效。浏览器缩放或短窗口使高度低于阈值时，会退回早期的纵向长页面和横向说明栏：标题、520px 预览区、说明和按钮彼此分离。

实际 Chrome 复现：1780×572 时作品区约 1248px 高，预览几乎在首屏之外，说明与两个操作区横向挤压。

第二个根因：原地缩放后，前面章节随视口重新排版，但页面保留旧 scrollY。1920×1080 进入作品区再缩到 1536×864，作品区顶部从导航下方 72px 偏到 -360px；继续缩放甚至会误入末章。重新打开锚点的静态尺寸矩阵无法覆盖这个问题。

## 修复

- 移除作品区 40 处重复布局规则，使用统一、仅按宽度切换的网格。
- 宽度至少 1100px 时保留说明与预览两栏，短窗口不再退回旧布局；窄窗口按标题、预览、项目说明依次排列。
- 预览按可用高度缩放；按钮保持独立排列，计数不换行，内容允许自然增长。
- 章节高度超出窗口可读区域时，滚轮和翻页键采用原生滚动，让使用者能读到本章底部；完整容纳时保留既有逐屏切换。
- 原地缩放时保留当前章节内的相对阅读位置，等待视口单位完成排版后校正。移动设备仅地址栏造成的高度变化不做主动校正。
- 未禁用浏览器缩放，未用 CSS zoom 或整体 transform 压缩正文。

## 验证

真实独立 Chrome 验证的 CSS 视口：1440×900、1780×572、1920×720、1280×800、1920×1080、960×540、768×1024、390×844、320×568。全部无页面水平溢出，预览有正常尺寸，桌面短窗口保持两栏。视口矩阵用于覆盖缩放造成的 CSS 可用空间变化，不将 DPR 缩放称作浏览器布局缩放。

- 1780×572 的两栏断言修复前失败，修复后通过。
- 1200×760 时滚轮 80px 修复前直接进入下一章；修复后仅滚动 80px，仍在作品区。
- 项目详情弹窗在 1780×572 时自然收缩至 492px 高，关闭按钮可用，不需额外改动。
- 不重新定位锚点，连续将视口从 1920×1080 改为 1536×864、1280×720、960×540，再恢复，作品区始终对齐导航下方，误差小于 1px；修复前首个尺寸就失败。
- 窄屏作品区滚动到中途再缩放，相对阅读进度维持约 18.52%；详情内缩放并关闭后仍在作品区，导航可直接跳到末章。
- 公开站 6 项现有测试与生产构建通过；独立代码审查无 P1/P2。

手工回归：进入作品区，将 Chrome 缩放依次切到 100%、125%、150%、200% 再恢复。确认标题/预览可找到、说明和按钮不横向挤压、内容较长时可以滚到章节底部；窄窗口能打开项目目录及详情并关闭。
