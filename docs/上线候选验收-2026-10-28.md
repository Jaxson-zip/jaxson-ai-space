## 本地重跑方法

先确认 55432、3110、4180 未被其他项目占用；保留已有开发预览 3102/4174。演练密码和密钥是固定合成值，不能用于生产。

```powershell
docker compose -f docker/compose.rehearsal.yaml up -d --wait db
$env:RELEASE_REHEARSAL='true'
$env:REHEARSAL_DATABASE_URI='postgresql://postgres:synthetic-rehearsal-only@127.0.0.1:55432/jaxson_rehearsal_local'
$env:REHEARSAL_MEDIA_DIR=(Join-Path (Get-Location) 'scratch/rehearsal-media')
pnpm --filter @jaxson/web exec tsx scripts/rehearse-database.mts prepare
docker compose -f docker/compose.rehearsal.yaml --profile runtime build
docker compose -f docker/compose.rehearsal.yaml --profile runtime up -d --no-build --wait
docker compose -f docker/compose.rehearsal.yaml exec -T web node apps/web/scripts/check-public-health.mjs
docker compose -f docker/compose.rehearsal.yaml exec -T worker node apps/web/scripts/run-index-worker.mjs --health
$env:WEB_TEST_URL='http://127.0.0.1:3110'
$env:TEST_PORTFOLIO_URL='http://127.0.0.1:4180'
$env:HANDOFF_HOME_URL='http://127.0.0.1:4180'
$env:PUBLIC_TEST_FIXTURE='true'
pnpm --filter @jaxson/web exec playwright test --config playwright.web.config.ts
```

prepare 会拒绝已有表的库；重复演练先退出该独立 Compose 项目并重新创建合成数据库，不要改工具去接受生产库。重建前只清理 `scratch/rehearsal-media` 中两个合成 PNG，避免 exclusive 写入拒绝。结束后 `docker compose -f docker/compose.rehearsal.yaml --profile runtime down --volumes`；此项目未绑定生产数据库卷，--volumes 仅移除本项目的演练匿名卷，不删除正式媒体和开发数据库。

## 获准发布后的执行顺序

1. 复核全部未提交变更和文案，提交、推送，等待 GitHub 的全部门禁成功。新门禁包含生产镜像构建和 PostgreSQL 演练；不能以本地结果代替该次 CI。
2. 只读核实当前生产提交、镜像、数据库迁移记录、媒体存储方式、空间和 worker 状态。最近生产基线是 10 月 27 日的 48b21cd 与 5 条迁移；执行时重查，不能盲信历史记录。
3. 创建并校验生产完整备份，记录位置。单独执行第 6 条迁移前，先按现有 restore 工具完成隔离恢复演练；不得向公开端口暴露恢复出的私人数据，也不把私有备份拉入仓库。
4. 复核新发布包 `migrations/003-security-update.sql` 与 SHA256SUMS，确认有 5 条预期旧迁移、users 新列尚不存在；经审批后单独执行 SQL。SQL只新增可空时间列并改新建项目默认值，不改现有项目状态。执行后验收 6 条历史记录、新列和 private 默认值，并确认旧应用仍能读取项目。
5. 备份并最小化同步服务器保留的配置：在 API 的 Caddy 站点加 `/api/chat` 64 KiB request_body 限制；Compose worker 加仓库同样的 healthcheck。保留生产域名、Access、代理头、现有挂载和其他服务。Caddy validate 通过再 reload。此配置操作与应用发布分开。
6. 使用主线提交手动触发发布。发布包验证必须保留迁移历史一致性门禁；失败时不能绕过。记录新旧 release、镜像标识和备份路径。
7. 检查首页、完整真实模型问答、全屏接续、来源链接、简历 PDF、旧 Word 跳转、视频 Range 和项目列表。清理两个旧 Word URL 的 CDN 缓存，并确认新回复 no-store；这不追溯删除已经下载的文件。
8. 匿名核对 admin/studio/私人接口、私有项目与私有附件仍不可读；登录后台核对现有记录、保存及邮件适配器。生产 S3 若使用公开桶或外部 CDN，须单独验证权限撤回，不得用本地文件结果替代。

## 失败与回退

- 新版健康检查失败会恢复 current 到旧 release，并重新启动、检查旧服务；健康 checker 从发布工具传入，兼容不含新脚本的旧镜像。新错误仍返回非零，不能把“已回退”当作“发布成功”。
- 应用回退通常保留新增可空字段及默认值，旧应用可忽略该列；本地已验证迁移的 down/up，但生产不应因应用回退而盲目删除列或回放数据库备份。
- 发布前尚未进入新版、或发布已完成时，退出清理不得误切换链接；本轮针对这些路径增加实际 shell EXIT trap 回归。
- 数据恢复是单独审批的操作，使用生产运维文档中的 scope/confirm 检查，不能用此处合成库命令替代。
