## 迁移时的组合关系

- **量化整套**：Freqtrade、中文 Web 与 Mihomo 代理同属量化目录体系；如果选择迁移，先一起核对策略/持久化数据、控制台与代理连接，不能只按单个容器名判断完成。
- **SalesPilot 整套**：core 依赖 gateway 和 db，web 依赖 core，nginx 依赖 web/core。迁移时保留其数据库、上传目录、模型配置与代理入口。它的 db 独立于官网 PostgreSQL。
- **官网整套**：portfolio、web、worker、Caddy、PostgreSQL 为本项目应用组合。迁移须保留数据库、媒体、角色/schema 边界与代理配置；不是复制静态首页即可。
- **OpenClaw**：还有独立配置、登录状态与私人接入，且会调用本站接口；如迁移，须单独核对会话状态与连接地址。
- **拾账验收实例**：有 `/data` 持久化挂载，迁移时须先核实其用途和当前数据，不把它当作可随意删除的临时空环境。
- **Cloudflare Tunnel**：是独立入口服务；迁移单个业务时核实对应入口规则，不直接把整个隧道随其中一个应用搬走。

若目标是优先保住官网，可先评估量化整套与 SalesPilot，再评估 OpenClaw。量化是已确认的主要 Swap 占用者。此排序只依据当前资源和组合关系，不代表业务重要性；没有替站长作出停服或迁移决定。持续高 steal 仍需服务商核实，减负不保证消除虚拟化层 CPU 等待。
