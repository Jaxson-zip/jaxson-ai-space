## 本次项目读取优化

- 浏览器读取 `https://jaxson.bond/api/showcase-projects`，与首页使用同一域名；AI 与 CMS 继续使用独立后台域名。
- 作品站服务通过 Docker 内网 `http://web:3000` 读取固定的匿名公开项目接口，避免绕公网回源。
- 进程内缓存最多 10 秒，同时到达的读请求合并。CMS 发布、更新、撤回后，新请求最迟在缓存到期时看到变化；这不是保存后立即失效的 webhook 缓存。
- 浏览器和 CDN 对该 JSON 收到 `Cache-Control: no-store`。已经打开的页面不会因缓存到期自动更新，仍需刷新页面。
- 不转发登录 cookie、Authorization、查询参数或任意 API 路径，不透传 Set-Cookie。CMS 故障返回 503，过期数据不作为故障兜底。
- 最长上游请求 5 秒，公开响应最大 2 MiB。项目不按数量截断；若数据达到此容量，需要改为分页接口。
- Docker 内网生成的上传封面地址转换为公开 CMS HTTPS 地址。
- 去掉首屏不再需要的后台域名预连接；简历 PDF 不缓存，避免替换文件后拿到旧版。

## Cloudflare 接入方案

当前权威 NS 为 `dns25.hichina.com`、`dns26.hichina.com`。本次尚未改 NS 或 DNS，也未启用 Cloudflare CDN。

1. 在本人正确 Cloudflare 账号的域名管理中加入或找到 `jaxson.bond`。Cloudflare One / Zero Trust 总览与域名 CDN 管理是不同页面。
2. 保存并逐条核对阿里云现有 DNS 记录，包括 `space`、其他 A/CNAME、MX/TXT、验证及邮件记录；不要只迁移本站两条记录。
3. 初次接入：`@` A → `198.44.177.170` 开启代理；`api` A → 同 IP 保持 DNS only。保留其他记录。普通完整接入需在注册商设置 Cloudflare 实际分配的 NS；若已有 DNSSEC，先按官方迁移步骤处理 DS。
4. SSL/TLS 使用 Full (strict)。源站已有有效 Let's Encrypt 证书；不要使用 Flexible。
5. 哈希 WebP 与 woff2 保持一年缓存，按源站缓存头处理；不要建立覆盖所有页面的强制缓存规则。首页、配置、公开项目 JSON、简历使用 no-store。
6. API 后台先保持 DNS only，可保留当前真实 IP 限流行为。若将来代理后台，要先配置受信任的 Cloudflare 转发来源，验证访客 IP 与限流；不要直接信任外部传入的 CF-Connecting-IP。
7. 接入后在实际访问网络重复测试：静态资源应出现 `CF-Cache-Status: HIT` 或合理的 MISS→HIT；项目 JSON 不缓存，CMS 登录和 AI 流式响应正常。CDN 效果以测量为准。

资料：[默认缓存行为](https://developers.cloudflare.com/cache/concepts/default-cache-behavior/)、[Full (strict)](https://developers.cloudflare.com/ssl/origin-configuration/ssl-modes/full-strict/)、[完整 DNS 接入](https://developers.cloudflare.com/dns/zone-setups/full-setup/setup/)。

外部密钥只写入服务器 root 私有的 `production.env`；OpenClaw 的密钥写入网关的受限环境。不要放到作品站前端、代码仓库或聊天记录中。
